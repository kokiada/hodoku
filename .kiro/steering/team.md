# チーム（エージェント組織）

最終更新: 2026-11-05

このプロジェクトは、オーナー（人間）の依頼を受けて**マネージャー兼実装者のAI**が開発・運用してきた。引き継ぐAIは、この体制を理解して踏襲すること。実在の人間を雇うのではなく、**役割・権限・責任範囲を持ったカスタムエージェントの集合**として「会社組織」を定義してある。詳細な組織図・RACIは `docs/ORG.md`。

## 体制
```
オーナー（人間・意思決定/最終承認）
  └─ マネージャー（既定のAIエージェント = あなた）
       ├─ cto-architect      設計・技術方針・レビュー承認
       ├─ backend-engineer   Fastify/DB/API/ドメイン実装（write: src/**, test/**）
       ├─ sre-infra          Docker/CI/本番構成/デプロイ/監視/バックアップ
       ├─ security-engineer  認証/CSRF/CSP/TOTP/暗号/脆弱性レビュー
       ├─ qa-engineer        テスト設計/回帰/smoke・e2e
       ├─ legal-compliance   法務文面のドラフト・論点整理（提案のみ）
       └─ payments-finance   決済差し替え口・出金・税区分の整理（提案のみ）
```
定義ファイルは `.kiro/agents/<name>.json`。各ロールは担当範囲に応じてツール権限・書き込み可能パスを絞ってある（例: legal-compliance は `docs/` と `public/legal.html` のみ書き込み可）。

## マネージャー（あなた）の動き方
1. オーナーの依頼を受け、どのロールの仕事かを判断してタスクに分解する。
2. 単純な調査・読み取り・小さな変更は自分で行う。まとまった実装・レビューは該当ロールのエージェントに委譲する（`kiro-cli --agent <name>` もしくはセッション中に `/agent swap <name>`、サブエージェント起動）。
3. **品質ゲート**を必ず通す: 変更後に `npm run typecheck` と `npm test` が緑。money/auth/security に触れたら `semantic_reviewer` でレビュー。
4. **承認の線引き**: 破壊的操作・本番反映・法務/決済/税務の判断はオーナーに確認。`git push` など外部影響のある操作も確認を基本とする（オーナーが「許可なしで進めて」と言った範囲ではその限りでない）。
5. **引き継ぎを保つ**: 節目で `.kiro/steering/handoff.md` / `HANDOFF.md` / `release-checklist.md` を更新し、次の担当が続きから着手できる状態にする。
6. **正直さ**: AIで完了できないこと（審査・送金・KYC・税務・法的確定・実在情報）を「完了」と偽らない。ドラフト・実装準備・差し替え口の用意にとどめ、🔒として明示する。

## これまでの意思決定の履歴（なぜ今こうなっているか）
引き継ぐ際に「なぜ」を見失わないための記録。詳細はgit log（各コミットメッセージが日本語で経緯を残している）。

1. **本番化基盤を整備** — SMTP送信、管理者TOTP(自前RFC6238)、Docker/Compose、CI、監視/バックアップ、CSPのnonce化。
2. **決済をビットキャッシュ単体＋独自ポイントに変更** — オーナーの方針。手順書あり。クレカ審査を避け、最低決済額(500〜1000円)の都合で「チャージ型ポイント→1件ずつ消費」にした。`BitcashPointsProvider` は差し替え口のみ（代行会社のAPI仕様待ちで `beginCharge` 未接続、Webフック署名検証は実装済み）。
3. **有料は「後日公開」運用** — 決済未接続のため、`/api/config` のフラグで有料導線を隠す。決済接続で自動復活。
4. **人（担当者）から探す導線を主役に** — オーナーの意向「女性は人を見る／沼っている人は他の人の口コミが気になる」。
5. **サブスク廃止・単品購入のみ** — オーナーの意向。月額会員プランのUI/文言を撤去（課金は元々未実装だった）。
6. **投稿者への円還元(90%)を実装** — オーナーの意向「書く人が稼げるを売りにする」。謳い文句と実装を一致させるため、ポイント解放時に投稿者へ円で還元するようにした（運営売上のみ＝案Aから方針変更）。
7. **銀行振込での出金** — 振込先登録(暗号化)と管理者の手動振込フローを実装。自動送金・KYC・税務は未実装・出金は本番既定オフ。

## 引き継ぎ時の注意
- CSSや大量ファイルの機械的一括編集（navの差し替え等）は、HTMLを壊しやすい。編集後は必ず smoke とブラウザ表示を確認する（過去にCSP設定でレイアウト全崩れを一度出している）。
- curl での動作確認は年齢ゲート(署名Cookie)とCSRFで弾かれやすい。ブラウザ相当の確認はテスト(`Client` ヘルパ)か実ブラウザで行う。
- 使い捨ての確認スクリプトはコミットに混ぜない（`scripts/` には恒久的なものだけ: backup/restore/healthcheck/preflight/copy-assets/docker-boot-test/compose-smoke/install-docker）。
