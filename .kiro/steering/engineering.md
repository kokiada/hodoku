# エンジニアリング規約（Hodoku）

このプロジェクトのすべてのエージェント・作業で守るルール。

## スタック・前提
- Node.js 22 + TypeScript（ESM, `"type": "module"`）。import は拡張子 `.js` 付きで書く（NodeNext）。
- Web: Fastify 5。DB: 本番 PostgreSQL（`pg`）/ 開発・テスト PGlite。**同じSQLが両方で動く**ことを壊さない。
- 依存の追加は最小限に。追加する場合はバージョンを固定（キャレット範囲にしない）。

## 品質ゲート（変更を「完了」とする条件）
1. `npm run typecheck` が緑（`tsc --noEmit`）。
2. `npm test` が緑（Vitest, 79件以上）。初回はPGliteのコールドスタートで遅いことがある。
3. 新機能・バグ修正にはテストを追加する。
4. 破壊的な変更や挙動差が出る場合は、何を検証したか・何を検証できていないかを明記する。

## セキュリティの不変条件（壊してはいけない）
- パスワードは scrypt。セッションID・メールトークンは**ハッシュで保存**（生値を保存しない）。
- 年齢ゲートはサーバー側の署名Cookie検証。未確認ならHTMLを返さず `/age` にリダイレクト。
- CSRF（double-submit）＋ Origin 検証。状態変更APIは必須。
- 有料口コミの本文は、サーバーが権限確認してからしか全文を返さない（未購入は冒頭50字）。
- 購入・返金・出金の金額は**サーバーが決定**。二重実行はDBの一意制約＋トランザクションで防ぐ。
- ユーザー投稿は `innerHTML` を使わず `textContent` / `window.h()` 経由で描画（XSS対策）。

## コーディング
- ドメインロジック（価格計算・類似度・フラグ・分配）は `src/domain/` の純粋関数に置き、テスト可能に保つ。
- DB抽象（`src/db/index.ts`）の `exec`（パラメータなし・複数文）と `query`/`tx`（パラメータ付き）の使い分けを守る。PGliteはパラメータ付きの複数文を実行できない。
- 日付は JSON 化でズレるため、SQL側で `to_char(... 'YYYY-MM-DD')` に整形して返す。
- 既存の DI パターンに従う: 依存は `src/index.ts`（合成ルート）で生成し、`buildApp({...})` に渡す。

## git / 運用
- コミットはオーナーの明示指示があるときのみ。`.env` や秘密情報をコミットしない（`.gitignore` 済み）。
- 本番反映・破壊的git操作はオーナーの承認を得る。
