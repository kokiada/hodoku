# 本番リリース前チェックリスト（Hodoku）

最終更新: 2026-11-05

このサイトは成人向け（女性用風俗）の口コミ・比較＋（将来の）口コミ有料販売サービス。
公開は**2フェーズ**で考える。

- **フェーズ1（無料公開）**: 店舗・担当者の比較と口コミの閲覧・投稿を公開する。**有料販売と出金はオフのまま**（`PAYMENT_PROVIDER=disabled`・`PAYOUTS_ENABLED=false`。購入は 503）。コード変更なしでこの状態で出せる。
- **フェーズ2（有料化）**: 口コミの有料販売・投稿者への出金を有効化する。売上と支払いが発生するため、決済・税務・特商法の項目が追加で必要になる。

各項目は、AI エージェントが完了できるもの（✅ 自動化可）と、実在の専門家・審査・オーナー承認が必須のもの（🔒 要人間）に分けて管理する。

> **重要（誤解しやすい点）**: 「有料をオフにすれば法務が不要」ではない。会員登録・口コミ公開を行う時点で、年齢確認・プライバシー・利用規約・投稿ガイドライン・口コミ公開の法的方針は**フェーズ1でも必須**。有料オフで外せるのは主に特商法の販売表記・決済審査・出金の本人確認/税務。

## フェーズ1 — 無料公開（有料・出金はオフ）

### 技術（✅ 自動化可）
- [x] 有料販売をオフにして安全に運用できること（本番既定 `PAYMENT_PROVIDER=disabled`・`POINTS_PROVIDER=disabled`・`PAYOUTS_ENABLED=false`、購入/チャージは不可）— 実装済み・プリフライトで検証
- [x] **投稿者への「円」還元** — 読者がポイントで口コミを解放すると、販売価格の90%が投稿者の円残高に入る（`ledger_entries` の `sale`）。既存の残高・出金・集計の仕組みを再利用。二重計上は `(ref_id,kind)` 一意制約＋`review_unlocks` 一意制約＋円購入とのクロスチェックで防止。マイページ（残高・今月の売上・販売数）にも反映。
- [x] **有料導線の見せ方の決定と実装** — 「後日公開」方針。`/api/config` の `salesEnabled`/`pointsEnabled` で出し分け
- [x] 口コミ投稿の導線 — ナビに「口コミを書く」、担当者未指定でも担当者ピッカーから選んで投稿可、担当者ページ/投稿画面で「稼げる（90%還元）」を訴求
- [x] 公開前プリフライト点検の自動化（`npm run preflight`、CIに組込み）— 本番で危険な設定が起動時に落ちることを機械的に確認
- [x] 削除・訂正の依頼フォームを実際に受付（`POST /api/removal-request`→監査ログ記録）
- [x] 法務ページをフェーズ1の実態に整合（会員課金・有料販売・出金の記述を落とし、無料公開＋「有料は後日」に。運営者情報の節を新設）
- [ ] 投稿審査・通報対応フロー（モデレーター運用）の最終動作確認 — qa/backend（テストは通過済み。運用手順の確定は運営判断）

### 🔒 要人間（AI では完了にできない）
- [ ] **プライバシーポリシーの確定** — `public/legal.html#privacy` にドラフトあり。**弁護士確認必須。**
- [ ] **利用規約・投稿ガイドラインの確定** — `public/legal.html#terms`/`#guideline` にドラフトあり。情プラ法の削除対応手順・ログ保存期間を含め**弁護士確認必須。**
- [ ] **年齢確認の方式確定** — 現状は自己申告の署名Cookie。追加確認の要否を法務と判断。
- [ ] **口コミ公開の法的リスク評価** — 実在の店舗・担当者の評判に関わる。公開可否・免責・反論権の整理。**弁護士確認必須。**
- [ ] **運営者情報の記入** — `public/legal.html#operator` はプレースホルダ。実在の運営者名・連絡先を公開前に記入。
- [ ] **ドメイン・SSL・本番サーバー** — 実ドメイン取得、HTTPS（Caddy 自動）、本番環境変数の設定。— オーナー/sre-infra

## フェーズ2 — 有料化（口コミ販売・出金を有効化）

### 技術（✅ 自動化可、ただし接続判断は人間）
- [ ] `PaymentProvider` の実装（審査通過した決済代行向け、差し替え口は `src/payments/provider.ts`） — payments-finance が実装準備
- [ ] 有料出品・購入・返金・出金の本番導線の最終確認（元帳・二重実行防止はテスト済み） — qa/backend
- [ ] **ポイント解放分の返金・取り消し方針** — 現状、ポイント解放（点消費→投稿者へ円還元）に対する返金/クローバック経路は無い（円購入の `decideRefund` のみ）。出金を有効化する前に、解放由来の還元を取り消し可能にするか方針決定が必要。ポイント消費は非返金・出金は既定オフのため現状は実害なし。
- [ ] 特商法表記ページの実装（文面は要弁護士確認） — frontend

### 🔒 要人間（AI では完了にできない）
- [ ] **決済プロバイダの審査・接続** — 成人向けは審査が厳しい。審査通過が前提。接続判断はオーナー。
- [ ] **出金の本人確認（KYC）・税区分** — 振込先口座の登録・暗号化保存・管理者の振込フロー（口座開示→手動振込→支払済み）は実装済み。残るは本人確認(KYC)・源泉徴収・インボイス、および実際の振込（手動運用 or 送金API接続）。**税理士・弁護士の確認必須。** 出金は既定オフ。
- [ ] **特商法に基づく表記の確定** — 販売主体（運営か投稿者か）・手数料・返金条件・事業者情報。**弁護士確認必須。**
- [ ] **利用確認（usage_verified）の運用確定** — 予約メール等での検証方法。現状はモデレーター手動。

## リリース判定
- **フェーズ1公開の可否**: 「共通の技術基盤」＋「フェーズ1」の項目がすべて完了して初めて公開可。🔒 が1つでも未完なら公開不可。
- **フェーズ2（有料化）の可否**: フェーズ1が本番稼働済みのうえで、「フェーズ2」の項目がすべて完了して初めて有効化可。
- マネージャーはオーナーに未完了項目を明示して判断を仰ぐ。決済・税務・法務・特商法の最終判断は実在の専門家＋オーナー承認が必須で、AI では完了にできない。

## セキュリティレビューの記録（2026-11-05）
TOTP/SMTP/config の変更は semantic_reviewer によるレビューを実施。指摘7件のうち次を修正済み:
- 2FAダウングレード（再setupでの無効化）→ `totp_secret_pending` にstagingし確定まで現役を壊さない形に修正。
- TOTPステップのアカウントロックアウト欠如 → `completeLoginWithTotp`/`confirm`/`disable` で既存のロックアウトを適用。
- コード使い回し（リプレイ）→ `totp_last_counter` で受理カウンタ以下を拒否。
- ロック状態の再確認 → `completeLoginWithTotp` で `locked_until` を再チェック。
- STARTTLSの平文送信リスク → `SmtpMailer` に `requireTLS`（587等）を設定。

残り: ステートレスチャレンジの5分TTL内リプレイは、ペアとなるTOTPコードが単回使用（カウンタ消費）になったため、同一ペアの再利用は実質的に不可。設計上サーバー側に状態を持たせない方針のため nonce ストアは導入せず、この理由で許容とする。
